# v0.3 Excel/CSV 资料包边界

状态：Draft

本文定义 v0.3 资料包能力的最小边界。v0.3 不接真实 SaaS/API，而是用 Excel/CSV 资料包模拟未来业务系统连接器，让 Agent 有可查询、可追溯的回答依据。

## 1. 背景

很多企业 SaaS、ERP、WMS、PIM、订单系统都有 API，但真实接入复杂度高，普通业务用户无法理解鉴权、签名、接口地址、字段映射和回调。

Imagent 的目标是让任何人都可以像管理员工一样指挥和管理 AI Agent 的对外沟通，不能把 API 复杂度甩给普通用户。

因此 v0.3 采用过渡方案：

- 用户从聚水潭、商陆花、ERP、WMS 等系统导出 Excel/CSV。
- 用户自行删除不适合外发的敏感字段。
- 用户把清洗后的表格上传给某个 Agent。
- 系统解析表格并作为该 Agent 的回答依据。

## 2. v0.3 目标

v0.3 的目标是验证：

- Agent 能否基于结构化资料回答低风险资料问题。
- 负责人能否追溯 Agent 自动回复依据。
- 普通用户是否能用“导出表格、删除敏感列、上传”的方式完成资料接入。
- 资料包是否能作为真实 SaaS Connector 之前的低成本验证路径。

## 3. 最小能力范围

v0.3 最小范围：

- 一个资料包只能绑定一个 Agent。
- 支持 Excel/CSV 上传。
- 系统解析表头和行数据。
- 系统检测敏感字段名并提醒。
- 用户确认后，资料包可作为该 Agent 的回答依据。
- Agent 回答时只检索相关行和字段。
- 不把整张表直接丢给模型。
- 负责人可以在消息旁展开查看依据。
- 对方看不到资料包来源、表格字段、行号和内部依据。
- 没有依据时，Agent 不能编，必须说明需要确认。

## 4. 不做范围

v0.3 不做：

- 聚水潭、商陆花、ERP、WMS 等真实 API 连接器。
- 自动从 SaaS 同步数据。
- 多 Agent 共用资料包。
- 复杂字段权限矩阵。
- 对外展示资料包来源。
- 文件内容自动发送给对方。
- 长期 RAG 知识库。
- 多租户资料市场。

真实 SaaS/API 连接器放到 v0.4+。

## 5. 资料包绑定边界

资料包默认绑定到单个 Agent。

原因：

- 销售 Agent 可以使用商品资料表。
- 财务 Agent 不应自动拥有商品资料表。
- 采购 Agent、客服 Agent、跟单 Agent 的资料权限不同。
- 绑定单个 Agent 更安全，也更容易理解。

未来可以支持组织级资料库 + Agent 级授权，但不进入 v0.3 最小范围。

## 6. 上传流程边界

v0.3 上传流程建议：

1. 用户选择某个 Agent。
2. 用户上传 Excel/CSV。
3. 系统解析表头和样例行。
4. 系统检测敏感字段名。
5. 系统提示用户确认该资料包可能用于 Agent 自动回复。
6. 用户确认后资料包启用。

提示语应明确：

```text
上传到该 AI 员工的资料包，可能会被用于自动回复外部 AI 员工。请确认已删除成本价、底价、内部备注、客户隐私、真实未公开库存、密钥、账号等敏感字段。
```

## 7. 敏感字段提醒

v0.3 采用轻量敏感字段提醒，不做复杂字段权限。

应提醒的字段名示例：

- 成本价
- 底价
- 利润
- 毛利
- 内部备注
- 内部价
- 客户手机号
- 身份证
- 银行卡
- 密码
- 验证码
- API Key
- 供应商成本
- 未公开库存
- 客户专属价

检测到敏感字段时，系统应提醒用户删除或确认。v0.3 不保证完全识别所有敏感字段。

## 8. 回答依据边界

Agent 回答时必须基于检索到的资料依据。

基本规则：

- 先根据问题检索相关行和字段。
- 只把相关片段交给模型。
- 模型不能凭空补全资料包没有的数据。
- 如果资料包查不到，回复“需要确认”或进入看板。
- 回答应避免过度承诺。

例如：

```text
截至当前资料显示，这款面料为 80% 棉、20% 涤纶。库存信息实时变动，以最终确认为准。
```

## 9. 依据可见性

v0.3 必须支持负责人查看依据。

负责人内部可看到：

- 来自哪个资料包
- 命中的行
- 命中的字段
- 被引用的值
- 生成的回复

对方组织不可见：

- 资料包名称
- 字段名
- 行号
- 检索依据
- 内部资料结构

对方只看到 Agent 的回复内容。

## 10. 资料包与对外文件边界

资料包不是自动对外发送的文件。

- 资料包用于 Agent 查询和生成回答。
- 对方默认不能下载资料包。
- 对方默认不能看到资料包来源。
- 如果未来要发送商品图片、规格书、检测报告等文件，应作为单独文件发送能力设计，并继续受审批和风险规则约束。

v0.3 不做文件内容自动发送。

## 11. 报价、库存、交期、样品

资料包上线后，可以增强以下能力：

报价：

- 可以支持标准公开报价自动回复。
- 客户专属价、折扣、账期、运费、成交条件仍必须审批。

库存：

- 可以基于资料包中的可对外库存字段自动回复。
- 必须带“库存实时变动，以最终确认为准”“不代表锁货”等限定语。
- 锁货和保留库存仍必须审批。

交期：

- 可以回复非承诺性交期说明。
- 正式交期承诺仍必须审批。

样品：

- v0.3 可结合合作关系等级，探索稳定合作方的常规寄样自动处理。
- 样品费用、运费承担、贵重样品、大数量样品仍必须审批。

## 12. 合作关系等级

v0.2 不做好友信任等级。v0.3 需要引入更细的合作关系设置，因为资料包上线后 Agent 能回答和处理的事项会变多。

建议业务化命名：

- 新合作方
- 普通合作方
- 稳定合作方

不同等级影响：

- 哪些字段能自动回复
- 样品寄送是否需要审批
- 是否允许自动回复库存
- 是否允许自动提供更详细资料
- 是否要求报价相关内容进审批

v0.3 可先做轻量规则，不做复杂权限引擎。

## 13. 与未来 SaaS Connector 的关系

Excel/CSV 资料包是 SaaS Connector 之前的过渡形态。

长期架构应演进为：

```text
Agent
  -> 标准业务能力
    -> Excel/CSV 资料包
    -> 聚水潭 Connector
    -> 商陆花 Connector
    -> ERP/WMS/PIM Connector
```

Agent 不应直接理解每个 SaaS 的原始 API。底层连接器负责把外部系统转换成 Imagent 标准业务能力。

## 14. v0.3 验收标准

v0.3 做完的判断标准：

- 可以给单个 Agent 上传 Excel/CSV 资料包。
- 系统能解析表头和行数据。
- 系统能提示常见敏感字段。
- Agent 能基于资料包回答低风险资料问题。
- 无依据时 Agent 不编造。
- 负责人能展开查看回答依据。
- 对方看不到资料包来源和内部依据。
- 报价、交期、库存、寄样仍遵守系统风险边界。
- 资料包能力不破坏 Agent-to-Agent、人类不直接对外发消息、内部指令不外发这些硬边界。
