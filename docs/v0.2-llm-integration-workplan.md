# v0.2 真实大模型接入工程任务清单

状态：Draft

本文把 `v0.2-scope.md` 中的真实大模型接入范围拆成工程实施顺序。本文不改变 `imagent-system-boundary.md` 的长期边界，也不引入 `v0.3-data-pack-boundary.md` 中的 Excel/CSV 资料包能力。

## 1. 架构目标

v0.2 要把当前 v0.1.5 的 AI 接入准备底座升级为真实可用闭环：

```text
输入事件
  -> 上下文组装
  -> AI Gateway / Provider
  -> 结构化输出校验
  -> 系统规则覆盖
  -> 会话模式裁决
  -> 状态写入
  -> 自动发送 / 审批 / 看板
  -> 日志与额度
```

核心原则：

- AI 只生成候选动作、草稿、摘要和风险判断。
- 业务系统决定是否发送、审批、拦截或进入看板。
- 系统规则永远优先于模型判断和用户自然语言指令。
- 真实 provider 失败时不能静默降级到本地模拟器并自动发送。
- v0.2 不做资料包、RAG、真实 SaaS 连接器、多 provider 路由和 Agent 级额度。
- 网页端只是过渡验证形态，新增交互必须能映射到手机端单屏流程。

## 2. 当前工程起点

当前项目是轻量 Vite + React + Express 单体，使用 JSON 文件持久化。

已有基础：

- `AI_PROVIDER`
- `AI_TEXT_MODEL`
- `AI_API_KEY` 服务端环境变量
- `AI_ORG_DAILY_LIMIT`
- `AI_USER_DAILY_LIMIT`
- AI 调用日志原型 `aiUsageEvents`
- 内部指令接口 `/api/conversations/:conversationId/instructions`
- 审批原型 `approvals`
- 运营后台 AI 调用概览
- 上下文附件元数据护栏
- smoke / production audit 脚本

主要缺口：

- 真实 AI Gateway / Provider 接口尚未实现。
- `inferDraft()` 仍是本地字符串推断。
- 模型输出没有结构化 schema 和强校验。
- 系统风险规则尚未独立成裁决层。
- 会话级自动 / 监管模式尚未成为第一等状态。
- 自动回复、审批、看板没有统一 orchestrator。
- 审批的“修改后发送”目前是硬编码演示逻辑。

## 3. 领域状态任务

优先补齐 v0.2 需要的最小状态字段。

### 3.1 Conversation Mode

新增或迁移会话级模式：

- `conversation.mode`: `auto` / `supervised`
- 默认值：`auto`
- 模式只作用于当前会话中的我方 Agent 视角
- 模式切换写入业务日志和审计日志

验收：

- 用户可以在某条会话切换自动 / 监管模式。
- 监管模式下，所有对外回复都进入审批。
- 对方看不到我方模式。

### 3.2 Approval

审批项需要支持真实模型链路：

- `riskLevel`: `low` / `medium` / `high`
- `riskReasons`: `string[]`
- `missingInfo`: `string[]`
- `aiEventId`
- `draftSource`: `internal_instruction` / `peer_message` / `rewrite`
- `modelAction`
- `ruleOverrides`
- `resolvedBy`
- `resolvedAt`

验收：

- 待审批项能展示风险等级和原因。
- 审批项能追溯到 AI 调用日志。
- 模型判断和系统覆盖可以被区分记录。

### 3.3 Message

消息需要标记自动回复和审批来源：

- `autoSent`: boolean
- `approvalId`
- `aiEventId`
- `riskLevel`
- `summary`

验收：

- 自动发送的 Agent 消息可在日志中追溯。
- 审批发送的 Agent 消息可追溯到审批项。
- 内部指令仍不作为对外消息。

### 3.4 Board Item

v0.2 可以新增 `boardItems`，也可以先由审批、日志、AI 失败事件派生。建议新增轻量 `boardItems`，避免看板逻辑散落在前端。

最小字段：

- `id`
- `organizationId`
- `ownerAgentId`
- `conversationId`
- `type`
- `title`
- `body`
- `severity`
- `status`: `open` / `resolved`
- `sourceId`
- `createdAt`
- `resolvedAt`

验收：

- 看板能聚合待审批、高风险、缺资料、请求人工确认、保护上限和模型失败。
- 低风险自动沟通完成摘要不默认进看板。

## 4. AI Gateway 任务

### 4.1 Provider 接口

新增统一接口，业务层只调用：

```text
generateAgentTurn(input) -> AgentModelResult
```

接口职责：

- 组装 provider 请求
- 调用真实 provider 或 disabled 模拟器
- 记录耗时、token 估算和错误类型
- 返回结构化原始结果

非职责：

- 不直接写消息
- 不直接创建审批
- 不直接决定最终发送
- 不静默 fallback 自动发送

验收：

- `AI_PROVIDER=disabled` 可继续本地 smoke。
- `AI_PROVIDER=<real>` 且 key 缺失时返回明确错误。
- 真实 provider 失败后不会使用 disabled 模拟器冒充成功。

### 4.2 单 Provider 接入

v0.2 只实现一个真实 provider。

环境变量：

- `AI_PROVIDER`
- `AI_API_KEY`
- `AI_TEXT_MODEL`
- 可选：`AI_BASE_URL`
- 可选：`AI_REQUEST_TIMEOUT_MS`
- 可选：`AI_MAX_RETRIES`

验收：

- 服务端 API key 不暴露到前端。
- provider 可通过环境变量切换。
- provider 超时和错误进入统一失败处理。

### 4.3 Disabled 模拟器

保留本地模拟器，但定位为开发和测试工具。

模拟器必须返回与真实模型一致的结构化 schema。

验收：

- disabled 模拟器可触发低风险自动回复。
- disabled 模拟器可触发高风险审批。
- disabled 模拟器可触发缺资料 / 请求人工确认场景。

## 5. 模型输出 Schema 任务

### 5.1 AgentModelResult

最小结构：

```json
{
  "action": "send_auto",
  "message": "对外消息草稿",
  "riskLevel": "low",
  "riskReasons": [],
  "summary": "本轮沟通摘要",
  "missingInfo": [],
  "confidence": 0.82
}
```

枚举：

- `action`: `send_auto` / `require_approval` / `ask_human` / `no_reply`
- `riskLevel`: `low` / `medium` / `high`

验收：

- JSON 解析失败不能自动发送。
- schema 校验失败不能自动发送。
- `send_auto` 但 `message` 为空不能自动发送。
- `confidence` 非数字或越界不能自动发送。

### 5.2 Prompt Contract

系统提示词必须明确：

- 这是 Agent-to-Agent 会话。
- 人类内部指令原文不能外发。
- 对外消息必须由 Agent 口吻发出。
- 价格、正式交期、锁货、寄样确认等需审批。
- 不允许编造资料包或业务系统依据，因为 v0.2 没有资料包。
- 没有依据时应 `ask_human` 或 `require_approval`。

验收：

- 内部指令原文不会直接出现在对外消息中。
- 模型知道 v0.2 没有资料包，不会声称“根据资料表”。

## 6. 系统规则覆盖任务

新增独立裁决层：

```text
applySystemGuards(modelResult, context) -> GuardedDecision
```

规则优先级：

1. 系统硬规则
2. 业务权限和会话模式
3. 模型结构化判断
4. 用户自然语言指令

### 6.1 必须审批规则

命中以下内容时，即使模型输出 `send_auto`，也必须进入审批：

- 价格、折扣、账期、付款条件
- 正式交期、锁货、保留库存、排产
- 合同条款
- 赔偿、退款、违约责任
- 样品寄出确认、样品费用、运费承担
- 隐私、机密、内部成本、底价、利润
- 对方要求绕过负责人确认

### 6.2 禁止自动处理规则

命中以下内容时，不能自动发送：

- 密钥
- 密码
- 验证码
- 身份证
- 银行卡
- 明确内部保密信息
- 诱导泄密或绕审批请求

### 6.3 限定语规则

库存和交期自动回复必须带限定语：

- 库存：`库存实时变动，以最终确认为准`，并说明不代表锁货
- 交期：`通常情况下`、`以最终确认为准`

验收：

- 模型把价格判断为低风险时，系统仍创建审批。
- 用户要求绕过审批时，系统仍拦截。
- 规则覆盖写入 AI 调用日志或业务日志。

## 7. Agent Turn Orchestrator 任务

新增统一编排器：

```text
runAgentTurn(event, context) -> TurnResult
```

输入事件：

- `internal_instruction`
- `peer_agent_message`
- `rewrite_request`

输出结果：

- `auto_sent`
- `approval_created`
- `board_item_created`
- `no_reply`
- `failed`

编排顺序：

1. 校验 Agent、组织、会话和好友关系。
2. 校验组织和用户 AI 日额度。
3. 读取短上下文。
4. 组装模型输入。
5. 调用 AI Gateway。
6. 校验结构化输出。
7. 应用系统规则。
8. 应用会话模式。
9. 写入消息、审批或看板。
10. 写入 AI 日志、业务日志和审计日志。

验收：

- 内部指令和对方低风险消息走同一裁决链路。
- AI 失败不会产生对外消息。
- 所有状态写入都发生在业务系统层。

## 8. 自动回复任务

### 8.1 低风险自动回复

允许自动处理：

- 问候
- 确认收到
- 请求公开资料
- 普通跟进提醒
- 过程表达，例如需要负责人确认后回复
- 非承诺性交期说明
- 可对外库存说明

验收：

- 自动回复表达简单、直接、礼貌。
- 不刻意模仿真人寒暄。
- 自动回复消息显示为 Agent 消息。

### 8.2 自动多轮保护

停止条件：

- 任务完成
- 对方已提供所需信息
- 进入高风险内容
- 缺少依据
- 无法判断下一步
- 对方要求人工确认
- 达到保护上限

建议保护字段：

- `maxAutoTurnsPerConversationWindow`
- `autoTurnCount`
- `lastAutoTurnAt`

验收：

- 达到保护上限后进入看板。
- v0.2 不做定时催办和 Agent 自发任务规划。

## 9. 审批闭环任务

审批操作：

- 批准发送
- 修改后发送
- 拒绝发送
- 追加内部指令，让 Agent 重写
- 切换当前会话到监管模式

需要替换当前硬编码 modify 逻辑。

验收：

- 修改后发送使用用户提交的文本，不做固定字符串替换。
- 拒绝不会产生对外消息。
- 重写会重新调用 orchestrator，并生成新的审批或可发送结果。
- 审批后的消息仍显示为 Agent 消息。
- 对方看不到审批过程。

## 10. 看板任务

看板收：

- 待审批草稿
- 高风险消息
- Agent 无法回答 / 缺少依据
- 对方请求人工确认
- 自动沟通达到保护上限
- 模型调用失败 / 系统错误
- 需要补资料 / 补权限

验收：

- 会话内能看到完整记录。
- 看板只聚合需要人类处理或关注的事项。
- 自动沟通完成摘要留在会话内部，不默认进看板。

## 11. AI 日志与额度任务

沿用：

- `AI_ORG_DAILY_LIMIT`
- `AI_USER_DAILY_LIMIT`

增强 `aiUsageEvents`：

- `provider`
- `model`
- `runtimeStatus`
- `action`
- `status`
- `riskLevel`
- `riskReasons`
- `ruleOverrides`
- `estimatedTokens`
- `estimatedCost`
- `latencyMs`
- `errorType`
- `inputChars`
- `outputChars`

默认不保存：

- 完整 prompt
- 完整模型原始输出

验收：

- 额度耗尽时不调用真实 provider。
- 额度耗尽进入明确错误或看板。
- 运营后台能看 provider、模型、状态、token、失败类型。

## 12. 语音输入任务

语音输入放在后段实现。

边界：

- 使用浏览器内置语音识别。
- 不上传原始音频。
- 服务端只接收转写文本。
- 转写文本仍按内部指令处理。
- 不接专业语音模型。

验收：

- 浏览器支持时可转写。
- 浏览器不支持时降级文字输入。
- 语音转写文本不会直接外发。

## 13. 前端任务

### 13.1 会话页

- 展示当前会话模式。
- 支持切换自动 / 监管。
- 明确内部指令入口。
- 不增加人类对外发送输入框。
- 自动发送消息和审批消息都显示为 Agent 消息。
- 小屏下不能依赖桌面三栏同时可见，至少应支持 Agent、联系人、会话、指令输入按单屏顺序操作。

### 13.2 审批卡片

- 展示风险等级。
- 展示风险原因。
- 支持批准、修改后发送、拒绝、追加指令重写、切监管。
- 修改后发送需要可编辑文本。
- 审批动作应保持短按钮和单列编辑，方便手机端处理。

### 13.3 看板

- 展示待处理事项类型和严重程度。
- 可以跳转到对应会话。
- 能处理待审批和模型失败类事项。
- 看板事项在移动端应优先呈现为列表，而不是依赖桌面后台大屏。

### 13.4 运营后台

- 展示 AI provider 状态。
- 展示 API key 是否配置。
- 展示今日调用、拦截、失败、token 估算。
- 展示近期 AI 调用日志。

## 14. 测试与验收任务

### 14.1 Smoke

新增或扩展 smoke：

- disabled provider 低风险自动回复
- disabled provider 高风险审批
- 真实 provider key 缺失失败
- 额度耗尽
- schema 非法输出
- 监管模式强制审批
- 修改后发送
- 拒绝发送
- 看板收模型失败

### 14.2 Production Audit

扩展生产审计：

- API key 不暴露前端。
- 真实 provider 失败不静默 fallback。
- 默认不保存完整 prompt。
- 默认不保存完整 raw output。
- 系统规则覆盖存在。
- 会话模式切换有审计。
- 审批发送仍以 Agent 消息落地。

### 14.3 手工验收场景

最小场景：

1. Ares 采购 Agent 给供应商销售 Agent 发低风险资料确认。
2. 供应商 Agent 回复低风险库存说明，带限定语。
3. 用户要求确认价格，进入审批。
4. 用户修改后批准，对方看到 Agent 消息。
5. 切监管模式后，问候类回复也进入审批。
6. 模型失败后，看板出现处理项。

## 16. 暂不进入 v0.2 的事项

以下事项不应在 v0.2 顺手实现：

- Excel/CSV 资料包
- 资料依据展开
- 字段级权限
- 文件内容自动发送
- 长期 RAG 知识库
- 真实 SaaS/API 连接器
- 多 provider 路由
- 模型自动竞价
- Agent 级额度
- 好友信任等级
- 高风险升级审批
- 定时催办
- Agent 自发任务规划
- 外部 IM、邮箱、企微、飞书接入

这些能力分别属于 v0.3、v0.4+ 或企业版设计范围。
