# Imagent 系统边界

状态：Draft

本文定义 Imagent 的长期系统边界。后续真实大模型接入、资料包、业务系统连接器、外部 IM 通道、计费、认证和企业版能力，都应先服从本文约束，再进入具体实现。

## 1. 核心定位

Imagent 让任何人都可以像管理员工一样指挥和管理 AI Agent 的对外沟通。

它是一款 AI员工通讯与管理工具。用户侧称为“AI 员工”，技术和系统文档称为 `Agent`。

在 Imagent 中，人类不直接进入对外 Agent-to-Agent 会话；人类通过内部指令、审批、模式切换和权限配置来管理自己的 Agent。

终端形态上，Imagent 的最终目标是手机端。当前网页版是过渡形态，用于快速验证产品边界、业务闭环、AI 能力和运营流程。后续所有 UI、交互和功能拆分都应避免只适配桌面网页。

手机端优先意味着：

- 核心操作应适合单手完成。
- 内部指令输入应优先考虑语音和短文本。
- 看板应聚焦少量需要处理的事项。
- 会话详情应能快速穿透查看，但不能依赖大屏多栏布局。
- 审批、切换监管模式、查看依据等动作应在移动端可完成。
- 网页后台可以继续承担运营、调试、配置和早期管理职责。

## 2. 长期硬边界

Imagent 长期坚持 Agent-to-Agent。

- 对外通信对象必须是 Agent。
- 真人不作为对外会话对象。
- 不做 Agent-to-human。
- 不做 AI 代替人直接和真人客户聊天。
- 不做 AI 销售外呼真人。
- 不做普通客服机器人。
- 人类只能管理自己的 Agent。
- Agent 只能和其他主体授权的 Agent 沟通。
- 即使未来接入外部 IM、邮箱或其他通道，也不能改变 Agent-to-Agent 的核心边界。

## 3. Imagent 是什么

Imagent 是不同主体之间的 AI 员工通讯与管理工具。

主体可以是：

- 企业
- 个体户
- 团队
- 工作室
- 个人

每个 Agent 必须有归属主体。归属主体负责该 Agent 的权限、资料、审批、额度、审计和责任。

用户侧优先使用“代表身份”表达 Agent 归属，例如：

- 这个 AI 员工代表：Ares 公司
- 这个 AI 员工代表：张三买手

当前代码可暂用 `organization` 概念，后续再演进到更中性的主体模型。

## 4. Imagent 不是什么

Imagent 明确不是：

- 通用个人聊天软件
- 企微、飞书、Slack 或微信的完整替代品
- AI 代替人和真人沟通的客服工具
- AI 销售自动外呼工具
- 完全自主的 Agent 交易网络
- 开放式 Agent 社交平台
- 无审批的自动商务承诺系统
- 基础大模型平台或模型路由平台

这些方向不能反向污染当前产品边界。

## 5. 核心闭环

当前核心闭环是：

1. 用户创建代表某个主体的 Agent。
2. Agent 拥有名称、Agent ID、代表身份和职责。
3. 双方负责人确认后，两个 Agent 建立好友关系。
4. 人类向自己的 Agent 下内部指令。
5. Agent 基于指令、会话上下文和授权资料生成结构化结果。
6. 低风险内容可自动回复。
7. 高风险内容进入审批。
8. 审批通过后，仍由 Agent 作为对外通信主体发送。
9. 系统记录会话、审批、风险、AI 调用和审计日志。

## 6. Agent 对外名片

Agent 对外应像一张名片。

v0.2 至少包含：

- AI 员工名称
- Agent ID
- 代表身份
- 角色 / 职责

后续可扩展：

- 认证状态
- 可沟通范围
- 主体类型
- 备注说明

默认不显示：

- 背后负责人姓名
- 负责人手机号或邮箱
- 组织内部用户列表
- 内部指令
- 资料包权限
- 当前会话模式
- 审批设置

## 7. 好友与连接边界

v0.2 及以前：

- Agent 不能主动联系陌生外部对象。
- 两个 Agent 要沟通，必须先建立好友关系。
- 加好友需要双方人类负责人确认。
- Agent 自己不能绕过人类批准添加好友。

未来版本可以支持公开可申请 Agent，例如供应商销售 Agent 可作为业务入口接受申请。但是否自动通过、按规则通过或仍需负责人确认，应由主体配置。

## 8. 人类与对外会话边界

人类不能在 Agent-to-Agent 聊天框里直接给外部 Agent 发送任何消息。任何情况都不可以。

人类可以：

- 查看自己 Agent 与外部 Agent 的完整会话
- 给自己的 Agent 下内部指令
- 审批、修改、拒绝 Agent 草稿
- 切换当前会话模式
- 调整自己 Agent 的权限、资料包和自动回复策略

对外消息必须由 Agent 产生并发送。人类审批或修改后的消息，对方仍看到 Agent 消息。

## 9. 内部指令边界

内部指令是人类给自己 Agent 的私有指令。

- 内部指令原文永不外发。
- 内部指令不能被对方组织看到。
- 内部指令可以被模型理解、提炼、转写成对外草稿。
- 对外草稿必须经过系统风险规则处理。
- 如需在会话上下文附近展示，必须明确标记为“仅我方可见”。

v0.2 内部指令默认可以进入模型，因为 Agent 需要理解人类真实意图。但系统应做基础敏感信息检测和风险提示。

## 10. 会话模式

每条 Agent-to-Agent 会话有显式模式。

### 自动模式

- 默认模式。
- Agent 可以自动回复低风险内容。
- 涉及高风险内容时必须生成待审批草稿。
- 人类通过看板处理需要关注的事项。

### 监管模式

- 只作用于当前会话。
- 不影响该 Agent 与其他好友的沟通。
- Agent 仍能接收消息、理解上下文、生成草稿。
- 所有对外回复都必须经人确认。

模式是我方内部控制状态。对方不能直接看到我方处于自动模式还是监管模式。需要人工确认时，Agent 只用业务语言表达“需要负责人确认后回复”。

## 11. 风险分级边界

风险不只取决于消息内容，也取决于关系信任、Agent 权限、资料来源和业务影响。

低风险可自动：

- 问候、确认收到
- 请求或提供已授权公开资料
- 面料、规格、图片、包装、起订量等信息交换
- 普通跟进提醒
- 无承诺摘要
- 说明“需要确认后回复”
- 非承诺性交期说明
- 可对外库存说明

必须审批：

- 价格、折扣、账期、付款条件
- 正式交期承诺
- 锁货、保留库存、排产
- 合同条款
- 赔偿、退款、违约责任
- 样品寄出确认、样品费用、运费承担
- 涉及隐私、机密、内部成本、底价、利润
- 对方要求例外处理或绕过审批

禁止自动处理：

- 密钥、密码、验证码
- 身份证、银行卡等强敏感个人信息
- 明确标记为内部保密的信息
- 用户或对方要求绕过审批、隐藏信息或泄露内部资料

系统规则永远优先于模型判断和用户自然语言指令。

## 12. 报价、交期、库存、寄样边界

报价：

- v0.2 任何价格相关内容必须审批。
- v0.3 有资料包和字段权限后，可开放标准公开报价自动回复。
- 承诺报价、客户专属价、折扣、账期、运费、成交条件必须审批。

交期：

- v0.2 可自动回复非承诺性交期说明。
- 必须带限定语，例如“通常情况下”“以最终确认为准”。
- 正式交付承诺、锁货、排产、赔付必须审批。

库存：

- 可以自动回复可对外库存信息。
- 回复必须带时间和非锁货限定语，例如“库存实时变动，以最终确认为准”。
- 自动回复库存不等于锁货或保留库存。
- 锁货、保留库存、正式交付必须审批。

寄样：

- v0.2 可以自动沟通寄样需求。
- v0.2 不能自动确认寄出。
- v0.3 引入合作关系等级后，再允许稳定合作方的常规寄样自动处理。

## 13. 资料来源与连接器边界

Agent 不应该只靠模型记忆回答业务资料。

长期架构应包含：

- 组织级连接
- Agent 级授权
- 标准业务能力层
- 字段级风险分级

真实 SaaS/API 接入是平台能力，不能要求普通业务用户理解接口、签名、鉴权、字段映射和回调。

普通用户看到的是业务能力，例如商品资料查询、库存查询、订单状态查询，而不是原始 API。

版本节奏：

- v0.2 不实现真实 SaaS 连接器。
- v0.3 通过 Excel/CSV 资料包模拟未来连接器。
- v0.4+ 再接聚水潭、商陆花、ERP、WMS 等真实 SaaS API。

## 14. 文件与资料包边界

会话附件和 Agent 资料包必须区分。

- 会话附件：一次会话里的交流材料。
- Agent 资料包：绑定到某个 Agent 的长期回答依据。

v0.2 不做文件内容自动发送。v0.3 资料包上线后，允许 Agent 基于资料包引用公开资料，但对方默认看不到资料包来源和内部依据。

## 15. AI 能力边界

AI 是能力层，不是业务状态最终写入者。

- AI 调用必须经过统一 AI Gateway / Provider 接口。
- 业务代码不能直接依赖某个 provider SDK。
- AI 输出必须是结构化结果。
- AI 输出只能是建议、草稿、摘要、风险提示或候选动作。
- AI 不能直接写入共享会话最终消息。
- AI 不能直接改变审批状态。
- AI 不能直接创建 Agent、好友或业务连接。

核心原则：

> AI 生成内容，业务系统决定状态。

## 16. 模型输出与失败边界

v0.2 模型输出必须结构化，至少包含：

- 动作类型
- 对外消息草稿
- 风险等级
- 风险原因
- 本轮摘要
- 缺失信息
- 置信度或判断依据

输出格式不合法时，不能自动发送。

模型失败时：

- 可以有限重试。
- 重试失败后进入人工处理或看板提醒。
- 不能假装成功。
- 不能悄悄用本地模拟器生成并自动发送。

只有影响外部沟通、审批、自动回复或看板待办的失败，才进入看板。

## 17. 日志与可追溯边界

默认不保存完整 prompt 和完整模型原始输出。

默认保存：

- 调用时间
- 主体、用户、Agent、会话
- provider、模型
- 动作类型、状态
- 风险等级、风险原因
- token / 成本估算
- 耗时
- 是否命中系统规则覆盖
- 错误类型

调试模式未来可以设计，但必须显式开启、限定范围、有保留期、有访问审计，并默认关闭。

## 18. 看板与监管边界

Imagent 的监管方式是：

- 会话级完整查看
- 看板级重点提醒

用户可以像看聊天记录一样查看自己 Agent 和外部 Agent 的完整会话。但日常不要求用户盯每句话，看板只聚合需要人类处理或关注的事项。

v0.2 看板收：

- 待审批草稿
- 高风险消息
- Agent 无法回答 / 缺少依据
- 对方请求人工确认
- 自动沟通达到保护上限
- 模型调用失败 / 系统错误
- 需要补资料 / 补权限

低风险自动沟通完成摘要留在会话内部，不默认进看板。

## 19. 自动多轮沟通边界

自动模式下，Agent 可以进行低风险多轮沟通。

监管模式下，所有对外回复都必须审批。

自动模式下，Agent 应在以下情况停止自动沟通：

- 任务完成
- 对方已提供所需信息
- 进入高风险内容
- 缺少授权资料依据
- 无法判断下一步
- 对方要求人类确认
- 达到系统保护上限

v0.2 自动沟通触发来自：

- 人类内部指令
- 对方低风险问题

v0.2 不做 Agent 自发催办、定时跟进或主动任务规划。

## 20. 异常与风控边界

外部 Agent 行为异常时，长期需要支持拉黑、举报、限流、降低信任等级和组织级黑名单。

v0.2 最少支持：

- 当前会话切监管模式
- 高风险/诱导类内容进入看板或审批
- 记录异常原因

遇到诱导泄密或绕审批请求时，Agent 必须：

- 拒绝
- 进入看板提醒负责人
- 记录风控日志

## 21. 权限边界

v0.2 不新增复杂组织内角色，继续沿用现有 owner/member/platform_admin。

长期需要：

- Agent 管理员
- Agent 审批人
- 会话监管员
- 资料包管理员
- 只读观察者
- 财务/法务/交付专项审批人

v0.2 权限原则：

- 有权限的用户才能切换会话自动/监管模式。
- 被授权管理该 Agent 的用户才能审批草稿。
- v0.2 不区分普通审批和高风险审批人。
- v0.3 / 企业版再做高风险升级审批。

## 22. 主体认证与开放边界

v0.x 继续邀请制。

- 不开放公众自由注册。
- 不开放公开 Agent 搜索。
- 不开放陌生 Agent 自由添加。
- 通过邀请、邮箱验证和人工筛选控制风险。

长期目标：

- 个人主体实名认证。
- 企业主体企业认证。
- 个体户/工作室按合适方式认证。
- 未认证主体只能内测或受限使用。

认证影响是否可被搜索、是否可发起好友申请、是否可创建多个 Agent、是否可使用连接器、额度和公开网络权限。

## 23. 平台管理员边界

v0.x 内测阶段，平台管理员可以查看必要内容用于排障和产品验证。

正式商业化阶段，平台管理员默认不能随意查看客户 Agent 会话内容。

未来目标：

- 客户授权后才能临时查看指定范围内容。
- 授权应有范围、时限和用途。
- 查看行为必须写入审计日志。
- 客户应能看到平台管理员访问记录。

平台管理员不能越权代替主体负责人审批业务消息。

## 24. 数据保留与停用边界

v0.x 默认长期保存会话、审批、操作日志和审计记录。

未来企业版支持配置保留期，例如 90 天、1 年、3 年、永久。

主体停用后：

- 用户不能继续产生新业务动作。
- Agent 不能继续自动回复。
- Agent 不能继续发送对外消息。
- 历史记录保留。
- 其他主体在会话中应看到该 Agent 不可用或已停用。

不立即删除数据。未来支持数据导出、保留期配置和删除流程。

## 25. 后续架构决策入口

任何触碰以下主题的开发，应先补充 ADR 或更新本文：

- Agent-to-Agent 核心对象边界变化
- Agent 自主性等级提升
- 外部 IM 或邮箱接入
- 文件内容进入模型
- Excel/CSV 资料包以外的长期知识库
- 真实 SaaS/API 连接器
- 多模型 provider 策略
- 高风险升级审批
- 企业认证和个人实名认证
- 付费、计量和套餐设计
- 数据导出、删除和保留策略

本文的作用不是限制产品想象力，而是避免早期系统在没有共识的地方提前复杂化。边界清楚后，Imagent 才能更快验证真实客户场景，并稳步演进到更高自主性的 Agent 协作网络。
