# v0.2 真实大模型接入范围

状态：Draft

本文定义 v0.2 的实现范围和验收边界。v0.2 的目标是把 v0.1.5 的 AI 接入准备底座升级为真实大模型可用闭环，但不扩大 Imagent 的长期系统边界。

## 1. v0.2 目标

v0.2 要完成：

- 真实大模型接入
- 结构化模型输出
- 内部指令理解
- 对外回复草稿生成
- 低风险自动回复
- 高风险审批
- 自动模式 / 监管模式
- 看板提醒
- AI 调用日志和额度

v0.2 仍以现有网页版推进实现和验证，但必须把手机端作为最终目标纳入设计约束。v0.2 不要求交付原生 App，但新增交互不应只在桌面多栏布局下成立。

v0.2 仍然坚持：

- Agent-to-Agent
- 人类不能直接对外发消息
- 内部指令原文不能外发
- 模型不能直接改业务最终状态
- 系统规则优先于模型判断

## 2. 必须真实可用

v0.2 必须真实可用的能力：

- 人类文字/语音内部指令理解
- 生成对外回复草稿
- 自动回复低风险消息
- 高风险识别并进入审批
- 待办/看板提醒
- Agent 之间低风险多轮自主沟通
- 自动模式 / 监管模式切换
- AI 调用日志
- 组织和用户每日额度

v0.2 轻量版本能力：

- 会话摘要：先做当前会话短摘要，不做长期记忆。
- 风险解释：先记录进审批原因，不做复杂解释系统。
- 语音输入：用浏览器内置语音识别；不可用时降级文字。

## 2.1 终端形态约束

Imagent 最终目标是手机端，网页版只是过渡。

v0.2 不做原生移动端，但工程实现应遵守：

- 核心流程能映射到手机端：选自己的 Agent、选对方 Agent、查看会话、下内部指令、审批草稿、切换监管模式。
- 新增 UI 不依赖桌面同时展示三栏才能理解。
- 看板事项必须能在移动端以列表方式处理。
- 审批动作必须足够短：批准、修改、拒绝、重写、切监管。
- 语音输入作为内部指令入口，应优先服务移动端使用习惯。
- 后续移动端可以复用同一套 API 和业务边界。

## 3. 不做范围

v0.2 不做：

- Agent-to-human
- 人类直接进入外部聊天框发消息
- 外部 IM / 邮箱 / 企微 / 飞书接入
- Excel/CSV 资料包
- 真实 SaaS/API 连接器
- 文件内容自动发送
- 长期 RAG 知识库
- 多 provider 同时路由
- 模型自动竞价或复杂 fallback
- Agent 级额度
- 复杂组织角色
- 高风险升级审批
- 好友信任等级
- 公开注册、公开 Agent 搜索、陌生 Agent 自由添加

## 4. Provider 边界

v0.2 采用统一 AI Gateway / Provider 接口。

- v0.2 只实现一个真实 provider。
- 保留 `AI_PROVIDER=disabled` 本地模拟器。
- 业务代码不能直接依赖某一家 provider SDK/API。
- provider 通过环境变量切换。
- v0.2 不做多个 provider 同时路由。
- v0.2 不做按任务自动选模型。

真实 provider 失败时，不能悄悄用本地模拟器生成并自动发送。

## 5. 模型输出格式

v0.2 模型输出必须是结构化结果，不能只返回自由文本。

结构化结果至少包含：

- `action`：`send_auto` / `require_approval` / `ask_human` / `no_reply`
- `message`：对外消息草稿
- `riskLevel`：`low` / `medium` / `high`
- `riskReasons`：风险原因
- `summary`：本轮沟通摘要
- `missingInfo`：缺失信息
- `confidence`：置信度或判断强度

业务系统必须校验模型输出格式。输出格式不合法时，不能自动发送。

## 6. 系统规则优先级

优先级固定为：

1. 系统硬规则
2. 业务权限和会话模式
3. 模型结构化判断
4. 用户自然语言指令

示例：

- 模型判断价格内容为低风险，也必须进入审批。
- 用户要求 Agent 绕过审批，也不能放行。
- 模型输出 `send_auto`，但系统检测到敏感字段，必须拦截。

## 7. 自动模式 / 监管模式

每条会话有显式模式。

自动模式：

- 低风险内容可自动回复。
- 高风险内容进入审批。
- Agent 可进行低风险多轮沟通。

监管模式：

- 只作用于当前会话。
- 不影响该 Agent 与其他好友。
- 所有对外回复都必须审批。
- Agent 仍可接收消息、理解上下文和生成草稿。

模式切换必须记录日志。

## 8. 低风险自动回复

v0.2 可自动处理：

- 问候、确认收到
- 请求公开资料
- 提供已知且可对外的普通信息
- 非承诺性交期说明
- 可对外库存说明
- 普通跟进提醒
- “需要负责人确认后回复”这类过程表达

自动回复表达应简单、直接、礼貌、少废话。核心目标是效率，不刻意模仿真人寒暄。

## 9. 高风险审批

v0.2 必须进入审批：

- 价格、折扣、账期、付款条件
- 正式交期、锁货、保留库存、排产
- 合同条款
- 赔偿、退款、违约责任
- 样品寄出确认、样品费用、运费承担
- 隐私、机密、内部成本、底价、利润
- 对方要求绕过负责人确认

审批支持：

- 批准发送
- 修改后发送
- 拒绝发送
- 追加内部指令，让 Agent 重写
- 切换当前会话到监管模式

审批后的对外消息仍显示为 Agent 消息。对方看不到审批过程。

## 10. 报价、交期、库存、样品

报价：

- v0.2 任何价格相关内容必须审批。

交期：

- v0.2 可自动回复非承诺性交期说明。
- 必须带限定语，例如“通常情况下”“以最终确认为准”。
- 正式承诺必须审批。

库存：

- v0.2 可以自动回复可对外库存信息。
- 必须带限定语，例如“库存实时变动，以最终确认为准”“不代表锁货”。
- 锁货、保留库存和正式交付必须审批。
- 没有依据时必须说明需要确认，不能编。

样品：

- v0.2 可以自动沟通寄样需求。
- v0.2 不能自动确认寄出。

## 11. 自动多轮沟通

v0.2 自动沟通触发来自：

- 人类内部指令
- 对方低风险问题

v0.2 不做：

- Agent 自发催办
- 定时跟进
- 主动任务规划

自动沟通应在以下情况停止：

- 任务完成
- 对方已提供所需信息
- 进入高风险内容
- 缺少依据
- 无法判断下一步
- 对方要求人工确认
- 达到系统保护上限

达到保护上限时进入看板提醒。

## 12. 看板范围

v0.2 看板收：

- 待审批草稿
- 高风险消息
- Agent 无法回答 / 缺少依据
- 对方请求人工确认
- 自动沟通达到保护上限
- 模型调用失败 / 系统错误
- 需要补资料 / 补权限

自动沟通完成摘要不默认进看板，只留在会话内部。

## 13. 语音输入

v0.2 使用浏览器内置语音识别能力。

- 可用时支持语音转文字。
- 不可用时降级文字输入。
- 不接专业语音模型。
- 不上传原始音频到服务器。
- 服务器只接收转写后的内部指令文本。
- 语音输入仍是内部指令，原文不能外发。

## 14. 日志和额度

v0.2 沿用：

- `AI_ORG_DAILY_LIMIT`
- `AI_USER_DAILY_LIMIT`

v0.2 记录 token / 成本估算，但不做强计费。

默认不保存完整 prompt 和完整模型原始输出。保存调用时间、主体、用户、Agent、会话、provider、模型、动作类型、状态、风险等级、风险原因、token / 成本估算、耗时、错误类型和规则覆盖情况。

## 15. 失败处理

模型调用失败时：

- 可以有限重试。
- 重试失败后进入人工处理或看板。
- 不能假装成功。
- 不能悄悄用本地模拟器生成并自动发送。
- 不向对方暴露内部模型失败细节。

只有影响外部沟通、审批、自动回复、看板待办生成的失败，才进入看板。

## 16. 最小上线验收

v0.2 做完的判断标准：

- 真实大模型接入成功。
- 内部指令能生成结构化结果。
- 低风险消息可自动回复。
- 高风险消息进入审批。
- 自动模式 / 监管模式可切换。
- 看板能收待审批、风险、失败、缺资料、对方请求人工确认和保护上限。
- AI 调用日志和组织/用户额度正常。
- 线上 smoke / production audit 通过。
- 不突破 Agent-to-Agent、人类不直接对外发消息、内部指令不外发、模型不能直接改业务最终状态这些硬边界。
